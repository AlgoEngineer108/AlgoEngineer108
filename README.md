## 🧮 The "algo" in Algo Engineer

Data engineering is mostly algorithms running on very large inputs. These are the patterns I use most:

| Problem | Naive approach | What I do instead |
|:--|:--|:--|
| Daily reload of a 2B-row table | Full scan and overwrite | Watermark plus incremental `MERGE` that only touches changed rows |
| Deduplicating events | `DISTINCT` over all history | Window function per key within a bounded late-arrival window |
| Slow joins | Shuffle both sides | Broadcast the small side, bucket or cluster on the join key |
| Distinct counts on dashboards | Exact `COUNT(DISTINCT)` | HyperLogLog sketches where approximate is good enough |
| Change tracking | Diff full snapshots | CDC from the database log with Debezium |
| Hot partitions | Bigger cluster | Salting skewed keys and fixing the partition strategy |

## 📜 Engineering rules

> **1.** Every load is idempotent. Rerun it, backfill it, nothing duplicates.
>
> **2.** Agree on the grain before writing a single line of SQL.
>
> **3.** Tests ship in the same PR as the model.
>
> **4.** No owner, no alert, no runbook = not in production.
>
> **5.** Measure before you optimize, and optimize the biggest cost first.
>
> **6.** Boring, well-documented pipelines beat clever ones.
